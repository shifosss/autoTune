What the DAG Shows

Seeds node_0001 and node_0002 are independent baselines with different hyperparameter configurations. Both are Pareto-optimal (rank 0) because they trade off differently: 0001 has better retention+cost, 0002 has better task score.
Branch node_0003 branches from 0001 with an aggressive LR increase (2e-4 → 1e-3). Task score jumps from 0.78 to 0.85, but retention drops from 0.95 to 0.84. Still rank 0 because task gain outweighs retention loss in Pareto terms.
Cliff node_0005 branches from 0002 with LR=2e-3. Retention crashes from 0.93 to 0.71 (δ=-0.22, below threshold -0.10). A DangerZone is created around its manifold coordinates. Future proposals near this region are blocked. Its potential is halved by the health penalty (0.76 × 0.5 × exploration).
Merge node_0006 merges 0001 and 0002 with weighted_avg (0.5/0.5). The merged checkpoint inherits knowledge from both parents. Result: best task score so far (0.87) with reasonable retention (0.90). Rank 0.
Graft node_0008 grafts the "technique delta" from 0004 (high-rank LoRA) onto 0003 (high-LR branch). Graft math: δ = 0004 - 0001, grafted = 0003 + δ. Achieves the best composite (0.88) by combining orthogonal improvements.
Dominated node_0009 is rank 2 (dominated) because node_0006 beats it on task (0.87 vs 0.81) and node_0004 beats it on retention (0.96 vs 0.91). Its checkpoint gets pruned. node_0005 is also rank 2, dominated by multiple nodes on every objective.

DAG-UCB Potential Walkthrough

With exploration_weight=0.5, N=9 executed, cliff_threshold=-0.10:

node_0008 (best composite, 1 child)
$$\text{potential}_{0008} = \bigl(0.88 + 0.5 \times \sqrt{\tfrac{\ln 9}{1+1}}\bigr) \times 0.89 = (0.88 + 0.52) \times 0.89 = 1.24$$
node_0005 (cliff, retention below threshold)
$$\text{potential}_{0005} = \bigl(0.76 + 0.5 \times \sqrt{\tfrac{\ln 9}{1+0}}\bigr) \times (0.71 \times 0.5) = (0.76 + 0.74) \times 0.355 = 0.53$$

The ×0.5 health penalty and low retention (0.71) slash the potential by more than half compared to a similar composite without forgetting.

node_0001 (seed, 3 children — heavily explored)
$$\text{potential}_{0001} = \bigl(0.78 + 0.5 \times \sqrt{\tfrac{\ln 9}{1+3}}\bigr) \times 0.95 = (0.78 + 0.37) \times 0.95 = 1.09$$

Despite being a lower-composite seed, decent retention (0.95) and moderate exploration bonus keep it viable. But 3 children reduce the bonus significantly.

Step 1: Normalization

Config Bounds

From config.yaml: lr ∈ [1e-5, 5e-3], rank ∈ [4, 128], warmup_ratio ∈ [0.0, 0.2]

$$\hat{\text{lr}} = \frac{\text{lr} - 1\text{e-5}}{5\text{e-3} - 1\text{e-5}} \qquad \hat{\text{rank}} = \frac{\text{rank} - 4}{128 - 4} \qquad \hat{\text{warmup}} = \frac{\text{warmup}}{0.2}$$

Example: node_0008 (lr=6e-4, rank=64, warmup=0.08) → (0.118, 0.484, 0.40)

Step 2: Weighted Mean

Centroid of Elite Points
$$\boldsymbol{\mu} = 0.43 \times \hat{\theta}_{0008} + 0.30 \times \hat{\theta}_{0006} + 0.18 \times \hat{\theta}_{0003} + 0.09 \times \hat{\theta}_{0007}$$ $$\approx (0.151,\ 0.412,\ 0.335)$$

The centroid is pulled toward the best performers. Note how it's biased toward moderate lr and moderate-to-high rank.

Step 3: Covariance & Eigendecomposition

Learned Covariance (after blending)
$$\boldsymbol{C} = \begin{pmatrix} 0.0082 & 0.0051 & -0.0012 \\ 0.0051 & 0.0194 & 0.0038 \\ -0.0012 & 0.0038 & 0.0029 \end{pmatrix}$$

Key observation: lr and rank are positively correlated (off-diagonal 0.0051 > 0). When one increases, the other tends to as well in successful experiments.

warmup_ratio has low variance (0.0029) — it matters less.

PC1 (75.7% variance): Moving along PC1 increases both lr and rank simultaneously. This is the "capacity" direction — the manifold has learned that model capacity (rank) and learning rate scale together in successful experiments.

PC2 (19.0% variance): Moving along PC2 increases lr but decreases rank. This is the "efficiency" direction — trading parameter count for learning speed.

Importance: lr (0.48) and rank (0.41) dominate; warmup_ratio (0.11) contributes little.

Proposal Generation Example

propose_direction(from_theta=node_0006.theta)

Suppose PC1 is sampled (probability ∝ λ&sub1; = 0.0231):

$$\hat{\theta}_{0006} = (0.118,\ 0.226,\ 0.30)$$ $$\hat{\theta}_{\text{new}} = \text{clip}\bigl((0.118,\ 0.226,\ 0.30) + 0.12 \times (0.42,\ 0.89,\ 0.18),\ 0,\ 1\bigr)$$ $$= \text{clip}\bigl((0.168,\ 0.333,\ 0.322),\ 0,\ 1\bigr) = (0.168,\ 0.333,\ 0.322)$$

Denormalized: lr ≈ 8.4e-4, rank ≈ 45, warmup ≈ 0.064

The proposal moves along the learned correlation: both lr and rank increase together, which the manifold has learned tends to improve performance.

Danger Zone Interaction

node_0005's Danger Zone

node_0005 caused a cliff at manifold coordinates:

$$\mathbf{z}_{0005} = \mathbf{V}_{:2}^\top (\hat{\theta}_{0005} - \boldsymbol{\mu}) \approx (0.41,\ 0.83)$$ $$r_{0005} = |\delta| \times s = 0.22 \times 0.5 = 0.11$$

Any future proposal whose projection falls within distance 0.11 of (0.41, 0.83) is blocked.

This effectively prevents proposals with very high lr (~2e-3) and moderate rank (~32) — exactly the configuration that caused catastrophic forgetting.

GPU Scheduling: Best-Fit Bin Packing

Algorithm

For each GPU $g$ with current allocations $A_g$:

$$\text{free}_g = \text{vram}_g - \text{safety\_margin} - \sum_{n \in A_g} \text{est\_vram}(n)$$

Select the GPU with the smallest $\text{free}_g \geq \text{needed\_gb}$ (tightest fit).

Constraint: $|A_g| < \text{max\_per\_gpu}$ (default 2 concurrent experiments per GPU).

NSGA-II Pareto Ranking ALGORITHM

dag.rerank_pareto() — Stratifies executed nodes into non-dominated layers.

Objective Space

Objectives

Each executed node $n$ is evaluated on up to three objectives:

$$\mathbf{f}(n) = \begin{cases} \bigl(\text{task}(n),\ \text{retention}(n),\ -\text{cost}(n)\bigr) & \text{if retention enabled} \\[4pt] \bigl(\text{task}(n),\ -\text{cost}(n)\bigr) & \text{otherwise} \end{cases}$$

All objectives are maximized (cost is negated).

Domination

Definition

Node $A$ dominates node $B$ (written $A \succ B$) if and only if:

$$A \succ B \iff \Bigl(\forall\, i:\ f_i(A) \geq f_i(B)\Bigr) \;\wedge\; \Bigl(\exists\, j:\ f_j(A) > f_j(B)\Bigr)$$

That is, $A$ is at least as good as $B$ on every objective, and strictly better on at least one.

Non-Dominated Sorting

Algorithm

Iteratively extract non-dominated fronts from the remaining population:

$$\begin{aligned} &S_0 \leftarrow \bigl\{\text{all executed nodes with metrics}\bigr\} \\ &r \leftarrow 0 \\ &\textbf{while } S_r \neq \emptyset: \\ &\quad F_r \leftarrow \bigl\{n \in S_r \mid \nexists\, m \in S_r : m \succ n\bigr\} \\ &\quad \forall\, n \in F_r:\ n.\text{pareto\_rank} \leftarrow r \\ &\quad S_{r+1} \leftarrow S_r \setminus F_r \\ &\quad r \leftarrow r + 1 \end{aligned}$$

Status Assignment

Rule
$$n.\text{status} = \begin{cases} \text{keep} & \text{if } n.\text{pareto\_rank} \leq 1 \\[2pt] \text{discard} & \text{if } n.\text{pareto\_rank} \geq 2 \end{cases}$$

Rank-0 = Pareto-optimal. Rank-1 = near-front (backup). Rank-2+ = dominated (checkpoints pruned).

The retention threshold (default 2) is configurable via orchestrator.checkpoint_retention_layers.

DAG-UCB Potential Scoring ALGORITHM

dag.recalculate_potential() — UCB1-inspired scoring that balances exploitation and exploration over a DAG structure.

Potential Formula

Core Equation
$$\text{potential}(n) = \Bigl(\underbrace{c(n)}_{\text{exploitation}} + \underbrace{w_e \cdot \sqrt{\frac{\ln N}{1 + k(n)}}}_{\text{exploration bonus}}\Bigr) \times \underbrace{h(n)}_{\text{retention health}}$$

where:

  • $c(n) = n.\text{composite}$ (or 0 if None)
  • $w_e = \text{scoring.exploration\_weight}$ (hyperparameter)
  • $N = \text{total\_executed}$ (number of completed experiments)
  • $k(n) = |\text{children}(n)|$ (direct child count in the DAG)

Retention Health Multiplier

Piecewise Definition
$$h(n) = \begin{cases} 1.0 & \text{if } n.\text{retention\_score} = \text{None} \\[4pt] n.\text{retention\_score} & \text{if } n.\text{retention\_score} \geq |\tau| \\[4pt] n.\text{retention\_score} \times 0.5 & \text{if } n.\text{retention\_score} < |\tau| \end{cases}$$

where $\tau = \text{scoring.retention\_cliff\_threshold}$ (e.g., $-0.10$).

Nodes below the cliff threshold have their potential halved, steering exploration away from regions that cause forgetting.

Intuition

Exploitation: High composite score $c(n)$ gives a high base potential.

Exploration: Nodes with fewer children get a larger bonus (the $\ln N / (1 + k)$ term grows as $k$ decreases). This prevents the agent from over-exploiting a single branch and encourages breadth.

Safety: The health multiplier penalizes nodes that caused retention drops, making the search avoid catastrophic forgetting regions.

CMA-ES Manifold Learning ALGORITHM

ManifoldNavigator.update() — Learns parameter correlations via covariance matrix adaptation. Triggered after every completion when |executed| ≥ 10.

Step 1: Normalization

Bounds Normalization

All hyperparameter vectors $\theta \in \mathbb{R}^d$ are normalized to $[0,1]^d$:

$$\hat{\theta}_i = \frac{\theta_i - \text{lo}_i}{\text{hi}_i - \text{lo}_i} \quad \text{for each parameter } i$$

where $(\text{lo}_i, \text{hi}_i)$ are the configured bounds from config.yaml.

Step 2: Selection & Weighting

Elite Selection

Rank all $N$ evaluated points by composite score. Take the top $\mu = \lfloor N/2 \rfloor$ (elite half).

Assign log-decay weights:

$$w_i = \ln(\mu + 0.5) - \ln(i) \qquad \text{for } i = 1, \ldots, \mu$$

Normalize: $w_i \leftarrow w_i / \sum_j w_j$ so that $\sum_i w_i = 1$.

Higher-ranked points get exponentially more weight.

Step 3: Mean Update

Weighted Mean
$$\boldsymbol{\mu}_{\text{new}} = \sum_{i=1}^{\mu} w_i \, \hat{\theta}_i$$

The centroid moves toward the best-performing region of the search space.

Step 4: Covariance Update

Weighted Covariance + Exponential Moving Average

Compute the weighted sample covariance from deviations relative to the old mean:

$$\boldsymbol{C}_{\text{sample}} = \sum_{i=1}^{\mu} w_i \, (\hat{\theta}_i - \boldsymbol{\mu}_{\text{old}})(\hat{\theta}_i - \boldsymbol{\mu}_{\text{old}})^\top$$

Blend with the running estimate using learning rate $\alpha = 0.3$:

$$\boldsymbol{C}_{\text{new}} = (1 - \alpha)\,\boldsymbol{C}_{\text{old}} + \alpha\,\boldsymbol{C}_{\text{sample}}$$

This exponential moving average prevents the covariance from changing too rapidly on noisy objectives.

Step 5: Eigendecomposition

Principal Components
$$\boldsymbol{C}_{\text{new}} = \mathbf{V} \, \boldsymbol{\Lambda} \, \mathbf{V}^\top$$

where $\boldsymbol{\Lambda} = \text{diag}(\lambda_1, \lambda_2, \ldots, \lambda_d)$ with $\lambda_1 \geq \lambda_2 \geq \cdots \geq \lambda_d$.

The columns of $\mathbf{V}$ are the principal components (eigenvectors), sorted by variance contribution.

Step 6: Effective Dimensionality

95% Variance Threshold
$$d_{\text{eff}} = \min\!\left\{k : \frac{\sum_{j=1}^{k} \lambda_j}{\sum_{j=1}^{d} \lambda_j} \geq 0.95\right\}$$

Only the top $d_{\text{eff}}$ PCs capture meaningful variance. Proposals and projections use this reduced subspace.

Step 7: Step Size Adaptation

Per-PC Step Size
$$s_j^{(t+1)} = \begin{cases} s_j^{(t)} \times 1.2 & \text{if } \lambda_j^{(t+1)} > \lambda_j^{(t)} \quad \text{(variance grew)} \\[4pt] s_j^{(t)} \times 0.8 & \text{if } \lambda_j^{(t+1)} \leq \lambda_j^{(t)} \quad \text{(variance shrank)} \end{cases}$$

Growing variance along a PC means that direction is productive; shrinking means it's over-explored.

Proposal: propose_direction(from_theta, pc_index)

Directional Step

If untrained (generation = 0): random unit vector with step 0.1.

If trained:

Sample PC index $j$ proportional to eigenvalue magnitude (if not specified):

$$P(j) = \frac{\lambda_j}{\sum_k \lambda_k}$$

Then step along the chosen PC:

$$\hat{\theta}_{\text{new}} = \text{clip}\!\bigl(\text{normalize}(\theta_{\text{from}}) + s_j \cdot \mathbf{v}_j,\ 0,\ 1\bigr)$$

where $\mathbf{v}_j$ is the $j$-th eigenvector and $s_j$ is the adapted step size.

Denormalize back to original parameter space.

Proposal: propose_candidates(from_theta, n)

Gaussian Sampling

If untrained: $n$ uniform samples from $[0,1]^d$.

If trained:

$$\hat{\theta}_i \sim \mathcal{N}\!\bigl(\text{normalize}(\theta_{\text{from}}),\ 0.01 \cdot \boldsymbol{C}\bigr) \quad \text{for } i = 1, \ldots, n$$

Clip to $[0,1]^d$, then denormalize.

Projection: project(theta)

Manifold Coordinates
$$\mathbf{z} = \mathbf{V}_{:d_{\text{eff}}}^\top \, (\hat{\theta} - \boldsymbol{\mu})$$

Projects a $d$-dimensional parameter vector onto the $d_{\text{eff}}$-dimensional manifold subspace. Used for danger zone checks and diversity computation.

Parameter Importance: parameter_importance()

Variance Contribution per Parameter
$$\text{importance}(i) = \frac{\displaystyle\sum_{j=1}^{d} \lambda_j \cdot |V_{ij}|}{\displaystyle\sum_{i'=1}^{d} \sum_{j=1}^{d} \lambda_j \cdot |V_{i'j}|}$$

Sums each parameter's absolute loading across all PCs, weighted by eigenvalue. Normalized to sum to 1.

Forgetting Detection ALGORITHM

ForgettingDetector — Retention cliff detection and manifold danger zone tracking.

Cliff Detection: check_cliff(node, parents)

Retention Delta

Compare node's retention against the best parent:

$$r^* = \max_{p \in \text{parents}(n)} \text{retention}(p)$$ $$\delta = \text{retention}(n) - r^*$$

A cliff is detected when:

$$\delta < \tau \qquad (\tau = \text{cliff\_threshold}, \text{ e.g., } {-0.10})$$

Danger Zone Creation

Exclusion Region

When a cliff is detected at node $n$:

$$\text{DangerZone} = \Bigl(\underbrace{\mathbf{z}_n}_{\text{center}},\ \underbrace{|\delta| \cdot s}_{\text{radius}},\ \underbrace{t_n}_{\text{cause technique}},\ \underbrace{|\delta|}_{\text{severity}}\Bigr)$$

where $\mathbf{z}_n = \text{project}(\theta_n)$ are the manifold coordinates, and $s = 0.5$ is the step size multiplier.

A larger retention drop creates a larger exclusion zone.

Zone Check: is_in_danger_zone_coords(coords)

Euclidean Distance Test

For a candidate at manifold coordinates $\mathbf{z}$:

$$\text{in\_danger} = \exists\, \text{dz} \in \mathcal{D} : \|\mathbf{z} - \mathbf{z}_{\text{dz}}\|_2 \leq r_{\text{dz}}$$

where $\mathcal{D}$ is the accumulated set of danger zones. Uses truncated dimensions: $\min(\dim(\mathbf{z}), \dim(\mathbf{z}_{\text{dz}}))$.

If any danger zone contains the candidate, the proposal is skipped by suggest_moves().

Branch & Merge Scoring ALGORITHM

Scoring formulas used by StrategyNavigator.suggest_moves() to rank proposals.

Branch Scoring (Single Parent)

Formula
$$\text{score}_{\text{branch}}(n) = \Bigl(c(n) + w_e \cdot \sqrt{\frac{\ln N}{1 + k(n)}}\Bigr) \times h(n)$$

Identical to DAG-UCB potential. Variables:

  • $c(n)$ = parent's composite score (or 0)
  • $w_e$ = scoring.exploration_weight
  • $N$ = total executed experiments
  • $k(n)$ = number of children of the parent node
  • $h(n)$ = retention health (see DAG-UCB)

Merge Scoring (Two Parents)

Formula
$$\text{score}_{\text{merge}}(A, B) = \Bigl(\bar{c} + w_e \cdot \sqrt{\frac{\ln N}{1 + m_{AB}}} + w_d \cdot \text{div}(A,B)\Bigr) \times \kappa(A, B)$$

where:

$$\bar{c} = \frac{c(A) + c(B)}{2}$$ $$m_{AB} = \text{count of prior merges between } A \text{ and } B$$ $$\text{div}(A,B) = 1 - \frac{\mathbf{z}_A \cdot \mathbf{z}_B}{\|\mathbf{z}_A\| \cdot \|\mathbf{z}_B\|} \quad \text{(cosine distance in manifold space)}$$

Complementarity Bonus

Formula
$$\kappa(A, B) = \begin{cases} 1.0 + |\text{task}(A) - \text{task}(B)| \cdot |\text{ret}(A) - \text{ret}(B)| & \text{if both have task and retention scores} \\[4pt] 1.0 & \text{otherwise} \end{cases}$$

Pairs where one parent is strong on task and the other on retention get a complementarity boost, incentivizing merges that combine orthogonal strengths.

Diversity Gate

Minimum Threshold
$$\text{div}(A, B) < 0.1 \implies \text{skip merge proposal}$$

Prevents proposing merges between near-identical parents (no benefit from combining).

Checkpoint Operations ALGORITHM

Mathematical definitions of the four checkpoint strategies: branch, weighted average, compose, and graft.

Branch (Copy)

Identity
$$\theta_{\text{child}} \leftarrow \theta_{\text{parent}}$$

Direct copy of the parent checkpoint. The training script starts from this base.

Weighted Average Merge

Element-wise Weighted Sum

Given parents $P_1, P_2, \ldots, P_m$ with weights $w_1, w_2, \ldots, w_m$ where $\sum w_i = 1$:

$$\theta_{\text{merged}}[k] = \sum_{i=1}^{m} w_i \cdot \theta_{P_i}[k] \qquad \forall\, k \in \bigcap_{i} \text{keys}(\theta_{P_i})$$

Only keys present in all parent state dicts are merged. Missing keys are dropped.

Compose Merge (LoRA)

Accumulated Delta from Base

Given base $P_0$ and additional parents $P_1, \ldots, P_{m-1}$:

$$\Delta = \sum_{i=1}^{m-1} \bigl(\theta_{P_i}[k] - \theta_{P_0}[k]\bigr)$$ $$\theta_{\text{composed}}[k] = \theta_{P_0}[k] + \Delta$$

Sums the deltas of all parents relative to a shared base, then applies the total delta. Useful for composing independent LoRA adaptations.

Graft

Cross-Branch Technique Transfer

Given a source experiment $S$ with source parent $S_p$, and a target parent $T_p$:

$$\Delta_S[k] = \theta_S[k] - \theta_{S_p}[k] \qquad \text{(technique delta)}$$ $$\theta_{\text{grafted}}[k] = \theta_{T_p}[k] + \Delta_S[k]$$

For keys not in $S$ or $S_p$, the target parent's value is kept unchanged:

$$\theta_{\text{grafted}}[k] = \theta_{T_p}[k] \qquad \text{if } k \notin \text{keys}(\theta_S) \cup \text{keys}(\theta_{S_p})$$

This "grafts" the learned technique from one branch onto a different branch of the DAG.

  1. adapter_model.safetensors (PEFT/LoRA)
